# Independent source review: type-only future layouts

Inspected the current `future_layouts.jl`, `future_call_layouts.jl`, `future_layout_fixtures.jl`, and staged measurement/check harness in the prototype worktree. No Julia execution was performed by this reviewer. Runtime qualification belongs to the root's Kaimon receipts.

No source blocker found in the reviewed discovery/precompile path. `FutureLayouts.precompile_future_layouts!` requires a live step-0 simulation; creates a separate model through the author-supplied builder; rejects shared mutable model/status/environment storage; deep-copies constants; applies bounded metadata policy before that future model's first logical compile; and performs only zero-step preparation before collecting types. Scientific execution is absent from the type collector. Cold call/context materialization is restricted to the explicitly disposable simulation. Both the default TaskLocalRNG state and Julia 1.13 Random.get_tls_seed() state are now restored on success and failure; the latter matters because XP construction uses Random.seed!(seed). The fixture guard compares copied states of both, and scientific model RNG fingerprints draw only from copies. Catalogue storage consists of types, global function objects and labels, not live scientific cells or environment samples.

The finite-request budget counts actual attempts. Reported accepted `Base.precompile` requests are not evidence of reused machine code. Actual generic kernel entry observations independently verify exact requested/accepted signature matches, while status/view matching compares canonical/local/kernel types and application identity. These are separate facts and should remain separate in results.

The PB fixture starts with all three original scientific applications targetless and registers generic gas-exchange objects through a pure controller. Its original Monteith/Fvcb/Medlyn methods are untouched. The XP future builder calls only fresh model constructors and public `add_organ!` for the first next Phytomer/Internode/Leaf; it executes no growth model, hard call or initializer. The schema order and transient targeted-initializer layouts may differ from fully prepared future shapes; the XP checker reports finite partial postbirth coverage rather than assuming completeness. PB/XP global row types are declared from the stored forcing rows through ordinary row preparation; no backend sampling is used for discovery.

Measurement construction, ordinary preparation, disposable blueprint/precompile, first execution and remaining execution are separate phases. Same cheap guard reads are inside the future phase for every arm; full snapshots and type/report formatting occur only after timed execution. Complete cost is the sum of those explicit phases, excluding module loading and final diagnostic serialization. Future-stage overhead must be included when judging any apparent first-growth reduction.

Qualification limits: the builder's no-science/no-external-side-effects rule is an author contract, not a Julia purity proof. Instrumented generic counters verify that contract for the generic pilot. Original downstream methods are not wrapped, so their exact entry signatures or global-forcing sample counts are not empirically observed by this harness. Downstream full-state/history/topology/type/RNG parity remains required. The current guards compare kernel counters where available, copied scientific RNG next draws and backend sample counters where available; the newly added canonical Status/Ref identity guard now compares every live canonical cell before/after the future stage and is charged inside that same timed phase for all arms. It retains only portable counts, not live references. No reviewed source path mutates those live cells.
